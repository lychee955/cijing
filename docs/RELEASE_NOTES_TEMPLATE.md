# Release Notes 写作模板

用于词境后续 GitHub Releases。每次复制下方正文到 `docs/RELEASE_NOTES_<版本号>.md`，替换占位符后，将正文粘贴到 GitHub Release 描述中。

## 写作约定

- Release 标题使用 `词境 v<版本号> · <一句话主题>`，Git 标签使用 `v<版本号>`，文件名中的版本不带 `v`。
- 开头用一两句话说明本版对用户最有价值的变化。
- 首发使用「本次亮点」概括已有功能；后续版本使用「本次更新」，只写相对上一公开版本的变化。
- 后续更新可分为「新增」「优化」「修复」，没有内容的分类直接删除；小版本也可合并成一个简短列表。
- 每条说明写清用户能做什么、什么体验得到改善或什么问题得到修复，避免堆砌内部实现、提交记录和测试数量。
- 下载文件名以本次实际构建产物为准。只列实际提供的平台和安装形式，不预先承诺尚未发布的包。
- 升级涉及数据、配置、兼容性或使用方式变化时，必须写清影响及用户需要执行的步骤。只有验证过才承诺数据保留或升级兼容。
- 已知问题只保留与本版用户相关的限制，删除已解决的问题；已实现但尚未完成实机验收的流程不能写成已验证可用。
- 首发使用「首次使用」说明 Token 和 AI 配置入口；后续版本通常使用「升级说明」，无需重复全部入门步骤。
- 发布前核对 `package.json`、`package-lock.json`、Git 标签、正文版本和附件文件名一致，移除所有占位符与不适用章节。
- 快照版必须标记 Pre-release、不设为 Latest，并明确未完成的验证及数据目录是否隔离。
- 参考快照发布说明：[词境 v0.0.2-snapshot.20261004.1](RELEASE_NOTES_0.0.2-snapshot.20261004.1.md)。

<用一两句话概括本次更新及其对用户的价值。>

### 新增

- **<功能名称>**：<用户现在可以做什么。>

### 优化

- **<体验或流程>**：<具体改善及用户能感受到的变化。>

### 修复

- 修复<触发条件下出现的具体问题>。

## 下载与使用

| 文件 | 用途 |
| --- | --- |
| `cijing-<版本号>-win-x64-setup.exe` | Windows x64 安装版 |
| `cijing-<版本号>-win-x64-portable.exe` | Windows x64 便携版，下载后直接运行 |

请选择本页 Assets 中对应的 `.exe` 文件。`latest.yml` 和 `.blockmap` 为更新配套文件，无需手动打开；`Source code` 是源码包。

## 升级说明

- **安装版**：<本版已支持并验证的升级方式。>
- **便携版**：<本版已支持并验证的替换或升级步骤。>
- **数据与配置**：<兼容性结论；如需备份、迁移或重新配置，写清具体步骤。>

## 已知问题与限制

- <当前仍存在、会影响用户的限制；必要时提供临时处理方法。>

## 问题反馈

欢迎通过仓库的 Issues 反馈问题或提出建议。请附上词境版本、操作系统版本、复现步骤和必要截图；请勿提交 Token、API Key 或未经检查的完整日志。
