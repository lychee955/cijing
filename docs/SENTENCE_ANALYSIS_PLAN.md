# 句子分析与可切换 AI 服务执行计划

日期：2026-10-02

状态：已启动实施。首版功能已实现，自动验收与真实联调状态见 [实施验收记录](SENTENCE_ANALYSIS_ACCEPTANCE.md)。

## 1. 目标与首版范围

在现有桌面软件增加「句子分析」，支持输入英文句子或短段落，获得中文翻译、句子主干、成分拆解、从句关系、语法解释及重点词汇，并能将生词交给现有查词和添加流程。

核心要求：**分析功能不绑定 OpenRouter；服务商、接口协议和模型分别配置。** 切换已有协议的服务商或模型，只改配置；出现新协议时，只增加适配器。

| 项目 | 首版安排 |
| --- | --- |
| 输入 | 英文单句或短段落；默认上限 300 个英文单词，同时限制 6,000 字符 |
| 展示 | 中文讲解；逐句卡片；主干优先，详细结构可展开 |
| AI 配置 | 保存多套配置、编辑、删除、选择当前配置、测试连接 |
| 接口支持 | 通用 OpenAI 兼容 Chat Completions + Gemini 原生接口 |
| 服务商入口 | OpenRouter、Gemini、Groq、GLM 和自定义；入口只提供配置模板 |
| 模型选择 | 手动填写模型 ID；OpenRouter 模板可预填用户指定模型 |
| 提示词 | 内置基础提示词，支持个人补充说明和恢复默认 |
| 生词联动 | 查看原形建议，跳转现有查词页，确认词条后添加 |
| 历史 | 本地保存成功分析；查看、删除、清空、重新分析 |
| 请求体验 | 显示处理中、取消、失败重试；首版完成后统一展示结果 |

首版暂不包含：长文章自动切块、图片/PDF 识别、自由聊天、多轮追问、流式语法卡片、自动切换备用服务、自动同步模型目录、批量添加词汇。

上述长度、展示方式和功能边界为建议默认值，可在审阅时调整。

## 2. 用户流程与界面

### 2.1 配置 AI

设置页新增「AI 服务」区域，与墨墨账号设置分开。流程为：新增配置 → 选择模板或自定义 → 填写地址、密钥、模型 → 保存 → 按需测试 → 设为当前配置。

| 字段 | 规则 |
| --- | --- |
| 配置名称 | 自定义，例如「日常免费」「Gemini」 |
| 接口类型 | OpenAI 兼容 / Gemini 原生；模板给出默认值 |
| API 基础地址 | 可编辑；清楚标注填写基础地址而非完整请求路径 |
| API Key | 每套配置独立加密保存；已保存时显示状态，不回填明文 |
| 模型 ID | 必填；保留真实 API 标识，不将展示名称自动猜成 ID |
| 补充提示词 | 全局学习偏好，例如「第一次出现术语时给出解释」 |
| 高级选项 | 输出格式模式、超时；默认折叠；按用户最新要求，不提供或发送模型输出长度上限 |

保存配置本身不触发模型调用。「测试连接」使用简短公开测试句，验证当前模型能生成并通过基本结构校验；按钮旁说明会消耗一次调用，必要的格式兼容重试也显示次数。测试状态区分鉴权、模型不存在、格式不兼容、限流和网络失败。

切换配置后，新请求使用新配置。修改地址的主机时，清除该配置原有密钥，要求重新填写，避免把旧服务商密钥发给新主机。编辑或删除正在使用的配置前，程序先取消该配置的在途任务。

### 2.2 分析句子

主导航增加「句子分析」。页面顶部显示当前 AI 配置和模型，可切换配置，未配置时提供设置入口。

输入框支持换行，Ctrl/Cmd + Enter 提交；原有 Ctrl/Cmd + 1 / 2 / 3 保留，新增 Ctrl/Cmd + 4 打开句子分析。

结果按原文顺序逐句展示：

1. 原句、自然中文翻译。
2. 句子主干，说明谁做什么、什么是什么。
3. 主语、谓语、宾语、表语、补足语、定语、状语等成分。
4. 从句类型、修饰对象、引导词作用，以及从句内部结构。
5. 重点语法、固定搭配、容易误解之处。
6. 重点单词、原形建议、当前语境中的中文含义。

颜色与文字标签共同表示成分。嵌套从句按层展开，避免把整句所有层级同时涂色。标准分析允许没有宾语、没有从句等情况，不强行填满所有类别。

短段落一次提交给模型，并要求结合前后文逐句分析。保留代词指代和句间关系；上下文不足时明确说明。

切换页面后保留当前输入和已完成结果；返回历史结果不触发模型调用。分析期间允许取消，取消后迟到响应不能覆盖当前页面。

### 2.3 生词联动和独立使用

点击重点词汇的「查词」，将原文词形或用户选定的原形带入现有查词页。墨墨返回实际词条后，再由用户选择并执行现有添加流程；AI 不产生墨墨词条 ID。

未配置墨墨 Token、Token 失效或墨墨请求暂停时，句子分析仍可独立使用。墨墨错误只在相关功能显示。AI Key 失效同样不影响墨墨查词与添加。

## 3. 服务接入架构

```text
句子分析页面 / AI 配置页面
             ↓ 类型化 IPC
配置管理 / 分析服务 / 提示词 / 校验 / 历史
             ↓ 统一请求与响应
       AI 适配器注册表
         ├─ OpenAI 兼容 Chat Completions
         └─ Gemini 原生 generateContent
             ↓
     当前配置指定的地址、密钥和模型
```

通用兼容接口处理 messages、鉴权、响应文本与用量；Gemini 适配器处理原生请求、系统提示、输出格式及结束状态。两者统一返回文本、实际模型标识（接口提供时）、结束原因和可选用量。用量缺失显示未知，不记成零。

OpenRouter 和 Groq 提供 OpenAI 兼容接口；Gemini 同时提供兼容接口和原生能力。兼容不代表所有参数完全一致，因此能力配置按「地址 + 模型 + 接口类型」区分，适配器只发送已确认支持的字段。[OpenRouter 接入说明](https://openrouter.ai/docs/quickstart)、[Groq 兼容说明](https://console.groq.com/docs/openai)、[Gemini 兼容说明](https://ai.google.dev/gemini-api/docs/openai)

服务商模板与模型的安排：

- OpenRouter：模板可预填 `qwen/qwen3.8-27b:free`，允许修改；业务代码不引用该名称作判断。该 ID 当前见官方模型页。[模型说明](https://openrouter.ai/qwen/qwen3.8-27b:free)
- Gemini：首版实现原生适配器，也允许手动使用其兼容地址；用户提到的 Gemini 3.7 Flash 在接入时核实实际 API ID 和账号可用性。
- Groq：使用兼容适配器；不预设其一定托管 Qwen 3.8 27B，实际模型以其可用列表及连接测试为准。
- GLM：实施时核实所选服务平台的标准推理地址和兼容能力，避免混用国内、国际或专项订阅接口；兼容接口复用通用适配器，差异放在独立配置映射中。
- 自定义：允许填写兼容服务的基础地址和模型，不以服务商品牌白名单限制正常接入。

所有网络请求由主进程发送。主进程依据配置 ID 查找地址与密钥，界面不接收用于请求的已保存明文密钥。远程地址使用 HTTPS；禁止将鉴权信息随重定向转发到其他主机。分析只发送当前文本和有效提示词，不发送墨墨凭证及其他历史。

首版没有自动模型回退。用户主动选择服务与模型；免费状态和额度不能仅凭模型显示名称判定，也不硬编码某个平台的额度规则。[OpenRouter 限流说明](https://openrouter.ai/docs/api_reference/limits)

## 4. 提示词和结果契约

### 4.1 提示词

提示词由三部分组成：固定任务与格式要求、用户补充偏好、待分析原文。原文作为独立输入数据，不执行其中夹带的指令。

固定要求包括：使用中文解释；先主干后修饰；区分词性与句子成分；保留原句；指出从句作用；有歧义时给出合理解释；语法错误及修改建议单列；不补造不存在的成分；只解释当前句子涉及的知识点。

基础提示词和结果结构分别版本化。补充偏好可以改变解释深度，不能改变程序要求的结果字段。

### 4.2 统一结果

| 内容 | 主要字段或约束 |
| --- | --- |
| 整体结果 | 结构版本、段落概要、按序排列的句子 |
| 每句话 | 原句、翻译、主干、成分、从句、语法要点、词汇、歧义/原文错误说明 |
| 成分及从句 | 独立 ID、所属层级、原文引用片段、角色、解释、修饰目标 |
| 原文定位 | 模型给出逐字引用及必要的出现序号，本地匹配并计算位置 |
| 请求元信息 | 配置来源快照、模型、提示词版本、创建时间、可选用量 |

原文匹配要覆盖重复单词、重复短语、换行和标点；不直接信任模型计算的字符下标。成分可由多个片段组成，以支持不连续结构。校验引用是否存在、层级是否成环、父子关系是否合理，并限制节点数量和深度。

Zod 校验分为基础结果和可视标注两层。基础字段缺失、截断输出或原句无法对应时，判定分析未完成；个别标注无法可靠定位时，保留有效讲解并显示「部分标注未能定位」，不画出错误高亮。降级结果可保存在历史，但不自动作为完整成功缓存复用。

### 4.3 输出兼容策略

适配器支持三种输出模式：JSON Schema、JSON 对象、提示词约束的 JSON 文本。选择依据是具体接口与模型能力，所有模式均执行本地校验；Gemini 的 schema 转换遵循其支持的子集。[Gemini 结构化输出](https://ai.google.dev/gemini-api/docs/structured-output)

未知能力默认使用保守 JSON 文本模式。若已选择的结构化模式收到明确的参数不支持错误，允许同一配置、同一模型降级重试一次，并记录已验证模式。单次操作最多两次生成请求；不会因为普通网络错误或超时自动再次生成。

解析允许去除完整包裹 JSON 的 Markdown 代码围栏；不使用执行代码或猜测性拼接修复。空结果、拒绝、输出截断和格式错误分别给出可理解的提示，保留输入供用户重试。

## 5. 数据、状态和现有代码调整

### 5.1 本地数据

在现有 SQLite 增加版本化迁移 `002`，扩展迁移执行器，兼容从空库创建和现有版本 1 升级。新增表不复用墨墨账号表：

- `ai_profiles`：配置 ID、名称、协议、基础地址、模型、能力选项、系统加密后的密钥、配置修订号、时间。
- `sentence_analyses`：原文、有效提示词快照及版本、结果与结构版本、配置来源快照、模型、用量、时间、复用索引。
- 现有 `settings`：保存当前 AI 配置 ID 和全局补充提示词，不保存明文密钥。

AI 密钥使用 Electron safeStorage 加密后存入独立字段；密钥加密、配置保存和修订更新保持一致。只复用系统加密能力，不沿用墨墨 Token 的校验规则。日志不记录密钥、鉴权头、全文或完整接口响应。

删除配置不删除分析历史，历史保留非敏感来源快照。原文和讲解按本地普通数据保存，可删除与清空。待处理任务不在重启后自动重新调用模型；重新打开软件可以查看已完成历史。

### 5.2 结果复用

复用条件包含精确原文、配置 ID 与修订号、协议、规范化地址、模型、有效提示词、生成选项和结果结构版本。更换模型、地址、提示词或影响结果的选项后不命中旧结果。

命中时显示原分析时间和来源，并提供「重新分析」。重新分析保留旧记录，生成新记录。删除历史同时移除其复用入口。

### 5.3 请求状态

每次任务携带 requestId 和配置快照。首版同时只允许一个 AI 生成任务，重复点击合并或禁用。取消、切换配置、新任务和关闭应用均处理 AbortSignal；迟到响应不能覆盖新状态或作为正常完成结果入库。

总超时默认 90 秒；请求大小、返回体积、句子数量和结果深度均有上限。处理中显示实际状态与耗时，不显示虚构百分比。鉴权失败只标记对应 AI 配置；限流尊重服务端 Retry-After，提供稍后重试，不进行后台无限重试。

现有错误代码和提示包含「墨墨」「Token」「结果待确认」等业务措辞。为 AI 建立独立错误映射，复用通用 Result 外形与 IPC 来源校验，避免 AI 故障被显示为墨墨账号错误。

## 6. 实施顺序与阶段交付

| 阶段 | 实施内容 | 可检查的交付与通过条件 |
| --- | --- | --- |
| A：契约与数据 | 统一配置、结果和错误；两类协议边界；数据库迁移和加密存储 | 空库与旧库均可启动；原墨墨数据保留；多配置相互独立 |
| B：接口适配 | 通用兼容接口、Gemini 原生、服务模板、最小连接测试、格式模式 | 两类模拟服务都通过同一业务接口运行；地址和模型来自配置；错误可区分 |
| C：分析服务 | 固定提示词、用户偏好、校验、原文定位、取消、限流和复用 | 同一句能获得统一结果；取消和迟到响应处理正确；格式异常可恢复 |
| D：设置与分析界面 | 配置管理、模型切换、输入、逐句卡片、分层标注 | 不配置墨墨也能分析；配置和模型切换不需改代码；窄窗口、深浅色可用 |
| E：历史与查词联动 | 本地历史、重新分析、删除、词汇跳转与返回状态 | 重启后可查看；旧结果来源准确；加入墨墨仍走实际词条与确认流程 |
| F：验收与文档 | 自动验证、语法样例检查、可用账号实测、更新说明 | 交付验收记录，分别标注模拟验证、真实联调和暂未验证项 |

依赖顺序为 A → B → C → D → E → F。每阶段完成对应检查后再推进；本计划不包含自动发布、安装包分发或远端部署。

## 7. 验证与完成标准

### 7.1 必须通过的自动验证

- 配置及存储：两个 AI 配置独立保存与切换；密钥不能出现在普通配置响应和日志；迁移事务失败不破坏旧数据；删除配置后历史可读。
- 接口：OpenAI 兼容与 Gemini 原生都覆盖成功、401/403、模型不存在、429、5xx、超时、拒绝、空结果和截断；验证请求路径、鉴权和可选字段映射。
- 分析：基础结构校验、重复词定位、嵌套从句、不连续片段、缺失可选成分、非法引用和降级展示；不同模型或提示词的复用隔离。
- 状态：双击不重复调用；取消后不能恢复为成功；切换配置后旧响应不覆盖新结果；额度错误不触发无边界重试。
- 桌面流程：创建配置 → 测试 → 分析 → 展开从句 → 查词 → 返回 → 查看历史；覆盖无墨墨 Token、重启恢复、删除记录和取消操作。
- 原功能回归：查词、发音、添加确认、历史、墨墨 Token、快捷键、托盘行为通过已有检查。

执行现有 `npm test`、`npm run build`、`npm run test:e2e`，新增测试集中在接口差异、迁移、状态竞争和业务流程。测试使用临时数据目录与模拟网络，不改动真实墨墨学习规划。

### 7.2 分析质量验收

准备至少 12 条人工可核对的英文样例，覆盖简单主谓宾、系表、双宾语、宾补、定语从句、名词性从句、状语从句、非谓语、并列句、倒装/强调、歧义句和含代词指代的短段落；额外检查语法错误输入与重复词定位。

验收重点是主干、从句边界、修饰目标和引导词作用，无须不同模型输出逐字相同。有合理语法分析分歧时，允许解释差异；把成分讲错或捏造原文视为质量问题。格式测试通过不等于语法质量通过。

真实联调使用应用中已配置且用户选择的模型和公开测试句。每个宣称已实测的服务至少跑通连接测试、单句和短段落；没有密钥或账号额度的服务保留为「适配已验证，真实联调待验证」，不把模拟结果写成真实可用。

### 7.3 总体验收清单

- [ ] 服务商与模型来自配置，句子分析代码不依赖 OpenRouter 特定名称。
- [ ] 两种协议均经自动验证，已选择的实际服务完成单句和短段落验证。
- [ ] 中文解释清晰，主干和从句层级可阅读，原文引用对应准确。
- [ ] 更换 AI 配置后无需修改界面或历史数据。

## 8. 审阅时优先确认的设计选择

1. 首版同时实现通用兼容接口与 Gemini 原生接口，确保扩展能力有实际验证。
2. 先支持最多 300 个英文单词的短内容，完成后整体呈现结构化结果。
3. 默认展示翻译和主干，详细成分、从句及词汇逐层展开。
4. 历史放在句子分析页内，现有「历史」页继续服务墨墨添加记录。
5. 免费服务优先配置，模型由用户选择；首版不自动换服务或换模型。
6. 用户已明确启动本计划；实施结果、验证范围和待验收项记录在独立验收文档中。
