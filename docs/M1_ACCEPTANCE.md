## 适配决定

2026-09-11 下载并保留 [官方 OpenAPI 快照](api_bundle.yaml)。规范中的 `GET /vocabulary` 返回 `{ voc: Vocabulary }`，`POST /vocabulary/query` 返回 `{ voc: Vocabulary[] }`。为了满足技术方案第 7.1 节的多结果选择，M1 使用后者，始终传 `{ spellings: [用户输入.trim()] }`，不开放批量添加。内部 lookup 契约相应返回 `Vocabulary[]`。

`POST /study/add_words` 只传一个已查询得到的词条 ID，`advance` 固定 `false`。确认请求使用 `/study/query_study_records` 的 `voc_ids` 过滤，`as_count=false`，只按返回记录的 `voc_id` 精确匹配，不使用今日列表或总数断言成功。

对照 [官方 CLI](https://github.com/maimemo/memo-api-cli/blob/main/src/client.ts) 支持 `success/data/errors` 包装与规范描述的直接业务对象。检查 HTTP、业务错误和关键字段。未知业务错误码没有被猜测为确定失败；写入返回未知错误、无效 JSON、错误字段类型、超大响应、超时或断网时保留不确定性。真实账号的查询、添加及记录响应均通过当前校验；未人为制造真实业务失败，具体业务错误码仍保守处理。

真实联调发现并修复：首次添加前的只读确认查不到记录时，应显示 `unconfirmed`（暂未查到记录），允许用户继续首次添加；只有已经发出且结果不明确的写请求才进入 `uncertain` 并阻止重发。增加了两个单元回归场景，并在端到端测试中加入“先确认、再首次添加”。

## 真实账号人工联调步骤

1. 启动应用，在设置中输入真实个人 Token；不要把 Token 写入本文件、源码、截图或聊天记录。检查保存状态，重启确认仍为已保存。
2. 在手机 App 开启自动同步，确认 Token 有查询单词、添加单词和查询学习记录的权限。
3. 选一个用户愿意加入学习规划且当前尚未加入的测试词，在下方登记拼写。查询并核对候选拼写。
4. 只提交一次添加。记录界面状态与时间；`added_count=1` 应显示「已加入学习规划」。在手机 App 同步后核实词条已加入。
5. 点击「查询学习记录」，核实匹配语义和可见延迟。按钮会重新读取服务端记录，不重复写入；已确认新增的操作不会因记录暂未同步而被改成失败。
6. 若返回零新增或结果待确认，仅执行「再次确认状态」。不要反复点击添加，不以短期查不到记录判断失败。
7. 无需故意制造真实写入中断或耗尽请求额度；这些分支已通过模拟测试。真实接口异常只记录脱敏操作名、HTTP 状态、错误代码和提示，修订适配后重跑模拟验证。
